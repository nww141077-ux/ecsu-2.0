# Сторонние библиотеки и материалы — учёт лицензий

**Статус: полный аудит лицензий ещё не зафиксирован.** Наличие `package.json` и lock-файла не означает, что лицензии всех компонентов уже проверены.

Для распространения NexaFlow / ECSU 2.0 необходимо отдельно проверить и учесть как минимум:

- npm production-зависимости из `package.json` и фактически разрешённые версии из lock-файла;
- транзитивные зависимости;
- Python-пакеты из каждого `backend/**/requirements.txt`;
- шрифты, иконки, изображения, шаблоны, тексты и скопированные фрагменты кода;
- условия внешних платформ и сервисов, включая poehali.dev.

## Сбор исходного отчёта

Из каталога frontend-проекта выполните команды в PowerShell. При необходимости установите инструмент аудита отдельно; не добавляйте его в production-зависимости только ради генерации отчёта.

```powershell
npx license-checker --production --json --out third-party-npm-licenses.json
```

Если команда не находит зависимости, сначала выполните `npm ci` (при наличии синхронизированного `package-lock.json`) или `npm install`. Проверьте, что отчёт содержит все установленные production-пакеты и их лицензии. Инструмент автоматизирует сбор метаданных, но не заменяет проверку исходных лицензий.

Для Python выполните аналогичную инвентаризацию в отдельном виртуальном окружении для каждого набора зависимостей. Запишите точную версию и лицензию каждого прямого и транзитивного пакета; проверьте лицензионные файлы и notices upstream-проектов.

## Перед распространением

1. Проверьте каждую лицензию по официальному репозиторию/пакету и зафиксируйте URL и дату проверки.
2. Сохраните обязательные copyright notices, тексты лицензий и атрибуции в дистрибутиве.
3. Разберитесь с пакетами, у которых лицензия отсутствует, неоднозначна или несовместима с планируемым распространением; при сомнениях получите юридическую консультацию.
4. Не распространяйте утверждение «All Rights Reserved» на чужие зависимости и материалы.
5. Сохраните отчёт аудита и версии lock-файлов вместе с архивом релиза.
