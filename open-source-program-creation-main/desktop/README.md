# ECSU 2.0 — Windows, локальная сборка

Desktop-версия теперь упаковывает frontend внутрь приложения и открывает его локально (`file://`), без загрузки сайта с Firebase Hosting или poehali.dev. В Electron-пакете запросы к `*.poehali.dev` блокируются, чтобы приложение не обращалось туда незаметно.

## Сборка

Требуются Windows, Node.js LTS, npm и интернет для установки зависимостей/build tools. В PowerShell из каталога `open-source-program-creation-main`:

```powershell
npm install
npm run desktop:build:win
```

Установщик: `release\ECSU-2.0-Setup-1.0.0.exe`. Ярлыки создаются установщиком NSIS.

Для проверки локально: `npm run desktop:dev`.

## Границы локального режима

- Интерфейс и ресурсы frontend входят в установщик. Провайдер интернета не требуется для открытия самого приложения.
- В desktop-сборке навигация использует hash-маршруты, подходящие для `file://`.
- Внешние API, серверная БД, авторизация, сканирование открытых источников, AI, загрузка/выдача документов и синхронизация не включены локально. Запросы к старым функциям poehali.dev намеренно блокируются; страницы, зависящие от удалённых API, могут показывать пустые состояния/ошибки.
- Это локальная офлайн-оболочка/прототип, а не автономная серверная система. Чтобы модули с данными заработали без poehali.dev, отдельно разверните свой backend и PostgreSQL, перенесите миграции, настройте локальный API и авторизацию; это не включено в установщик.
- Не вводите реальные пароли, банковские реквизиты или личные документы в режим, пока собственный защищённый backend не развернут.
